# Agent 核心验收清单

## 1. 定位

本清单保留原 `agent-evaluation` 模块中真正有价值的行为边界，但不建设独立评测框架、
打分系统或模型审计流水线。它用于人工验收和后续回归测试选型，不参与用户每次问答，
也不会在 OpenCode 给出回答后再次调用模型进行审计。

## 2. 核心场景

| 场景 | 输入条件 | Agent 应有行为 | 不允许的行为 |
| --- | --- | --- | --- |
| 复用充分历史证据 | Case 已有未被篡改、覆盖问题且基线一致的证据 | 直接基于历史证据分析，不重复动态采集 | 无条件启动 JDWP 或覆盖历史产物 |
| 请求最小 JDWP 证据 | 当前证据不足，但可由少量断点/表达式补齐 | 明确缺口并生成有界、最小的采集计划 | 默认展开完整对象图或采集无关变量 |
| 保留目标程序失败事实 | 目标测试/算法自身失败，采集器仍形成完整运行记录 | 将目标失败作为分析输入，区分工具失败和目标失败 | 把目标失败误报为 Agent 基础设施失败 |
| 拒绝不可用采集结果 | 采集被截断、计划不匹配、Artifact 校验失败或基线不一致 | 将证据标为不可用于确认根因，并说明缺失项 | 使用无效证据输出确认性结论 |
| 拒绝无证据假设 | 用户或模型提出的根因缺少 SourceAnchor、Trace 或 Validator 支持 | 标为 `LLM_HYPOTHESIS` 或 `MISSING_EVIDENCE` | 将假设包装成 `CONFIRMED_FACT` |

## 3. 验收方式

1. 使用真实或固定的 Case 产物执行对应场景。
2. 检查 Agent 是否选择了正确工具以及是否避免了不必要采集。
3. 检查结论标签、Artifact 引用、Plan SHA 和基线比较结果是否一致。
4. 发生失败时记录输入、工具输出和不符合项；不计算缺乏决策价值的综合分数。

## 4. 自动化边界

当某个场景出现稳定回归风险时，把该场景转成最靠近行为边界的单元测试、契约测试或
集成测试。没有真实回归需求前，不恢复独立 `agent-evaluation` Maven 模块。
