# 07 决策提案：最小执行控制、可继续调查与逐条证据资格

- 状态：本地实施方向已获用户批准；正式架构决策与发布文档随对应实施阶段同步，不表示实现已通过验收。
- 日期：2026-10-06；版本：1.0。
- 影响：修订 ADR-018 的调查/门禁语义，保留原生 MCP、宿主模型和共享 Runtime 边界。
- 批准后在正式 ADR 目录记录编号或更新 ADR-018，并链接本包；本轮不擅自改旧 ADR 批准状态。

## 1. 决策

继续采用“宿主中的模型子 Agent + 版本化角色资产 + 多 MCP 工具 + 服务端共同入口”。Coordinator 是内部显式代码，不是模型必须先调用的工具、不依赖 AOP、不调用 LLM。

强制项只放身份、预算、执行安全、不可变证据、冻结检验、可解引用来源和逐条资格。模型仍自由选择源码分析路径、假设和采集轮次。

Gap 表示证据需求，可以多 Plan/多 Collection 继续；Truth 与 HypothesisEffect 正交；结论等级由逐条 Gate 唯一计算；自由文本机制只能按推断展示，确认事实由服务端 typed 见证渲染。

公司扩展能力由自己的真实 Catalog 注册。Plan 预检是共享确定性能力；它可以继续作为独立 MCP 工具帮助模型提前纠错，关键检查又由采集入口共享，因此不依赖模型牢记调用顺序。

## 2. 为什么有价值

| 原风险 | 目标机制 | 可以兑现的保证 | 不应宣称的保证 |
|---|---|---|---|
| 模型跳过必要准备 | 每个 Handler 共同入口检查 | 不满足前提时业务实现不执行 | 模型一定理解所有拒绝原因 |
| 多轮遗忘或改口 | 不可变调查与具体评估 | 历史反证、UNKNOWN、条件版本都可恢复核查 | 模型永远不忽视结果 |
| 同数据不同资格 | 确定性评估与统一效果解释 | 同版本同输入得到相同资格 | 不同模型必然同一解释 |
| 摘要错配因果 | 具体见证及范围、源码入口 | 无关记录不能冒充同实体/调用事实 | 任意因果关系可由代码证明 |
| 失败后盲重试/进程残留 | 操作日志、短事务、取消清理 | 可证明回放/恢复，不盲目重新执行 | 传输失败时无条件 exactly-once |
| 扩展工具各自为政 | typed Catalog + 统一生命周期 | 有明确接入点和完整性测试 | 未知工具零成本即插即用 |

这套机制解决的是工程执行与证据使用的稳定性；复杂算法推理的稳定性是源码可达性、可靠观测、模型分析和质量评测共同作用的结果。不能把整个提升都归功于“加一个 Coordinator”。

## 3. 明确删除的过度约束

- 删除“每个动态探索先造假设、至少两假设一反驳”的全局要求。
- 删除“一 Gap 一 Plan”“UNRESOLVED 永久终态”。
- 删除“FALSE 一律反驳”的约定。
- 删除状态投影/因果图/总 Gate 重复计算互相封顶的全局终态。
- 删除模型自填另一份宿主 Completion 状态；仅保留服务端 Finalization。
- 不把 knowledge、Resources、Prompts、Roots 都当核心必需能力。

这些不是取消质量门禁；相关反证、未知、截断、基准不一致和未建立关联依然限制对应 Claim。移除的是与业务问题无关的流程仪式或重复真相源。

## 4. 被否决的替代

| 方案 | 否决原因 |
|---|---|
| 只加更长 Skill，不改服务 | 无法保证多工具身份/重试/取消/证据资格；仍由模型记忆维护状态 |
| 暴露一个 coordinator Tool 要模型先调 | 可跳过；没有强制经过同入口 |
| 一个万能 MCP 工具包所有动作 | 巨大联合参数/权限，错误难定位；统一入口不需要统一工具名称 |
| MCP 服务调用第二个模型评审 | 叠加推理随机性、上下文/凭据/成本，不是确定性保证 |
| 把自由文本边做自动语义验证 | 本批没有可靠通用算法；容易伪装成证据充分 |
| 全量源码/对象图/Raw 一次发给模型 | 无界上下文、注意力偏差、性能与隐私风险 |
| 为公司统一重写全部工具 | 丢失已有预检等能力，扩大回归；职责映射即可 |
| 常驻 JDWP 调试会话顺便实现 | 涉及线程暂停/测试继续/状态污染的新生命周期，超出本次收敛整改 |
| 提前引入 LangGraph/数据库/队列 | 现有用例+追加仓库能表达需求，本批没有换基础设施的证据 |

## 5. 可控成本与真实风险

新增成本：调用入口维护、契约演进、短事务/幂等、见证索引解析、预检和质量评测。新增抽象数量按 03 限定，不造通用工作流 DSL；不把所有内容塞进 Coordinator。

风险一：过严资格导致拒答。用相关 Claim 范围、探索不强造假设、正确有界解释可接受以及 E03 错误拒答门槛约束。

风险二：服务端事实与模型解释混写。typed 事实使用 canonical summary；推断单独分级，真实宿主 Eval 检查越级。宿主最终自然语言不能由标准 MCP 强制时明确降低保证。

风险三：持久化/取消复杂度。采用最小短锁和原子 batch，不宣称跨多个文件分布式事务。恢复只处理可证明的派生/归档，不能自动重跑 UT。

风险四：旧数据/接口不兼容。版本化只读转换与整体发布/回滚，禁止把旧宽引用直接升级成确认级。

## 6. 决策成立条件

设计层面职责和数据闭环已给出，可以进入实现评审；功能可靠性必须通过 T01—T23、真实动态和宿主测试证明。分析准确性/稳定性必须通过 E01—E03 证明。

公司现状盘点与业务 Case 真值是公司实施/质量验收的外部输入；缺少这些资料不应靠猜测补齐。接受本决策不等于接受“已解决全部复杂算法根因不稳定”的宣传。
